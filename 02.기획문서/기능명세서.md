## 2. 기능 상세

### F-001. 사진 촬영 식사 인식

| 항목 | 내용 |
|------|------|
| 설명 | 사용자가 카메라로 즉시 촬영하거나 갤러리에서 기존 사진을 업로드하면, LLM 비전 API가 이미지 내 음식 종류·구성 요소를 다중 객체로 검출하고 예상 칼로리 및 매크로(탄수화물/단백질/지방)를 자동 산출한다. REQ-005의 "15초 완결 플로우" 중 1~2단계(촬영, 자동 인식)를 담당한다. |
| 입력 | - 카메라 촬영 이미지(JPEG/PNG, 모바일 브라우저 `<input capture>` 또는 MediaStream API)<br>- 갤러리 선택 이미지(기존 파일)<br>- (선택) 사용자 계정 ID, 식사 시간대(아침/점심/저녁/간식) |
| 처리 | 1. 클라이언트에서 이미지 압축(장변 1600px 이내, EXIF 위치정보 제거 — REQ-015) 후 업로드<br>2. 서버가 이미지를 LLM 비전 API(벤더 추상화 계층, NFR-007)에 전달<br>3. 응답에서 음식명·구성 요소·기본 배식량(1인분 기준)·예상 칼로리/탄단지를 파싱<br>4. 식약처 외식 영양성분 DB 표준치와 매칭하여 보정값 산출(F-002 연계)<br>5. 결과를 카드 형태 JSON으로 반환 |
| 출력 | - 인식된 음식 카드 목록(음식명, 구성 요소별 분할, 예상 칼로리, 탄/단/지)<br>- 기본 배식량 단위(그릇/접시/인분)<br>- 인식 신뢰도(내부 스코어, 화면 비노출) |
| 예외 처리 | - 인식 실패/저신뢰도: 대체 후보 3개 리스트 제공, 1탭으로 재지정 또는 키워드 검색 폴백(REQ-006)<br>- API 타임아웃(3초 초과, NFR-001): 로딩 UI 유지 후 재시도 또는 수동 검색 유도, 15초 목표(REQ-005) 초과 방지<br>- 이미지 업로드 실패(네트워크 단절): 로컬 임시 저장 후 재전송 안내<br>- 항상 노출: "AI 분석 수치는 추정치이며 의학적 조언이 아닙니다", 알레르기 미감지 경고 문구(REQ-012) |
| 관련 화면 | 촬영/업로드 화면, 인식 결과 확인 화면, 후보 재선택 팝업, 수동 검색 화면 (화면설계서 #9에서 상세 확정 예정) |
| 관련 API | `POST /api/meals/recognize` (이미지 업로드 및 비전 인식 요청), `GET /api/foods/search?q=` (수동 검색 자동완성) — API스펙(#7)에서 상세 정의 예정 |

### F-002. 배식량 보정 슬라이더 (사람 언어 UX)

| 항목 | 내용 |
|------|------|
| 설명 | F-001에서 인식된 음식의 배식량을 그램(g) 대신 "반 공기/1공기/1접시/1인분" 등 사람이 실제로 말하는 단위로 조절한다. 조절 즉시 칼로리와 영양성분이 비례 재계산되며, 화면에는 그램 수치를 노출하지 않는다. |
| 입력 | - F-001 인식 결과(음식별 기본 배식량 단위, 기준 칼로리/매크로)<br>- 사용자의 슬라이더 조작 값(0.5인분 ~ 2.0인분, 0.1 단위 증감) |
| 처리 | 1. 음식별 기본 단위를 식약처 외식 영양성분 DB 표준 중량(예: 1공기=210g)에 매핑<br>2. 슬라이더 값(배수)에 기준 칼로리/매크로를 곱하여 실시간 재계산<br>3. 내부 저장 시에만 그램 환산값을 함께 기록(양방향 매핑), 화면 표시값은 항상 "그릇/접시/인분" 단위 유지 |
| 출력 | - 보정된 배식량 단위(예: "밥 1/2공기")<br>- 보정된 칼로리/탄단지 실시간 값<br>- 저장용 그램 환산값(내부 데이터, 비노출) |
| 예외 처리 | - 표준 중량 DB에 없는 음식: 유사 카테고리 평균값으로 대체 후 "추정치" 표시<br>- 슬라이더 범위(0.5~2.0인분) 초과 조작 시도: 최대/최소값에서 정지, 추가 조작 무반응<br>- 그램 노출 회귀 방지: 화면 렌더링 전 그램 단위 필드 필터링 로직을 프론트엔드 공통 컴포넌트에 강제 |
| 관련 화면 | 인식 결과 확인 화면 내 배식량 슬라이더 컴포넌트, 저장 확인 화면 |
| 관련 API | `PATCH /api/meals/{id}/portion` (배식량 보정값 저장), `GET /api/foods/{id}/portion-map` (표준 중량 매핑 조회) |

### F-003. 체중 목표 및 칼로리 밸런스

| 항목 | 내용 |
|------|------|
| 설명 | 온보딩 시 증량/감량/유지 중 목표를 설정하면 일일 권장 섭취 칼로리 및 목표 매크로를 자동 계산한다. 대시보드에서는 목표 유형에 따라 칼로리 밸런스를 다르게 시각화한다 — 증량은 초과분을 긍정적 잉여(녹색/파랑)로, 감량/유지는 잔여 칼로리 게이지로 표시한다. |
| 입력 | - 온보딩 입력값: 목표 유형(증량/감량/유지), 현재 체중, 목표 체중, 신장, 연령, 성별, 활동 수준<br>- 일별 누적: F-001~F-002 기록 칼로리, (선택) 운동 소모 칼로리 |
| 처리 | 1. 입력값으로 기초대사량(BMR) 및 활동대사량(TDEE) 산출<br>2. 목표 유형별 일일 권장 칼로리·단백질 목표 계산(증량: TDEE+300~500kcal, 감량: TDEE-300~500kcal, 유지: TDEE)<br>3. 당일 누적 섭취 칼로리와 목표치를 비교하여 밸런스(잉여/잔여) 산출<br>4. 목표 유형에 따라 렌더링 분기: 증량→긍정 잉여 게이지, 감량/유지→잔여 칼로리 게이지 |
| 출력 | - 일일 기준 칼로리/단백질 목표<br>- 당일 칼로리 밸런스(잉여 또는 잔여 수치)<br>- 목표 유형별 게이지 UI 데이터, 축하 애니메이션/뱃지 트리거 여부(증량 목표 달성 시) |
| 예외 처리 | - 온보딩 목표 미선택: 저장 차단, 3가지 중 1개 필수 선택 검증<br>- 비정상 입력값(체중 0 이하 등): 클라이언트 유효성 검사로 차단<br>- 증량 목표 초과 섭취 시 경고색·부정 문구("초과되었습니다") 노출 금지 — UI 컴포넌트 레벨에서 색상/문구 화이트리스트 강제 |
| 관련 화면 | 온보딩(목표 설정) 화면, 홈 대시보드(칼로리 밸런스 게이지) |
| 관련 API | `POST /api/users/goal` (목표 설정 저장), `GET /api/dashboard/balance?date=` (일일 밸런스 조회) |

### F-004. 맞춤 운동 추천

| 항목 | 내용 |
|------|------|
| 설명 | F-003에서 산출된 당일 칼로리 밸런스와 사용자의 체중 목표에 따라 운동 유형·시간·예상 소모량을 제안한다. MVP는 정적 규칙 기반 추천으로 구현하며(서비스기획서 4장 F-4 MVP 범위), 적응형 알고리즘 고도화는 향후 로드맵 항목이다. |
| 입력 | - F-003 산출값: 당일 칼로리 밸런스(잉여/초과분), 목표 유형<br>- 사용자 프로필: 체중, 활동 수준 |
| 처리 | 1. 정적 규칙 테이블 조회(예: 초과 300kcal → 유산소 30분, 증량 목표 → 근력 운동 우선)<br>2. 목표 유형별 우선순위 적용: 증량→근력 운동, 감량→유산소 운동<br>3. 운동 3종(유형/시간/예상 소모 칼로리) 카드 생성 |
| 출력 | - 추천 운동 카드 목록(최소 1개 이상): 운동명, 예상 소요 시간, 예상 소모 칼로리 |
| 예외 처리 | - 식사 기록이 없는 날: 추천 카드 미노출(밸런스 데이터 부재) 또는 기본 유지 운동 안내로 대체<br>- 밸런스가 큰 폭으로 음수/양수(극단값)인 경우: 규칙 테이블의 최대/최소 구간값으로 캡핑하여 비현실적 추천 방지 |
| 관련 화면 | 홈 대시보드 하단 운동 추천 카드 영역 |
| 관련 API | `GET /api/recommendations/exercise?date=` (당일 추천 운동 조회) |

### F-005. 기록 히스토리 및 대시보드

| 항목 | 내용 |
|------|------|
| 설명 | 날짜별 아침/점심/저녁/간식 식사 기록과 칼로리 요약을 캘린더 형태로 조회하고, 주간 평균 칼로리 섭취량 및 체중 변화 추이를 그래프로 제공한다. |
| 입력 | - 조회 대상 날짜/기간(일간, 주간)<br>- 사용자 ID |
| 처리 | 1. 선택 기간 내 저장된 식사 기록(F-001~F-002 결과) 및 체중 입력 이력 조회<br>2. 날짜별 식사 카드 리스트 및 끼니별 칼로리 합산<br>3. 주간 단위 평균 섭취량·체중 변화 추이 계산 및 시계열 데이터 생성 |
| 출력 | - 일별 식사 사진 썸네일 + 칼로리 리스트<br>- 주간 평균 섭취량 꺾은선 그래프 데이터<br>- 체중 변화 추이 그래프 데이터 |
| 예외 처리 | - 기록 없는 날짜 조회: "기록 없음" 빈 상태(empty state) 표시<br>- 데이터 다건 조회 지연: 페이지네이션 또는 최근 30일 기본 제한 적용 |
| 관련 화면 | 히스토리(캘린더) 화면, 주간 리포트 화면 |
| 관련 API | `GET /api/meals?date=` (일별 기록 조회), `GET /api/reports/weekly?week=` (주간 요약 조회) |

## 3. 요구사항 ↔ 기능 추적 매트릭스

| 요구사항 ID | 요구사항 명칭 | 매핑 기능 |
